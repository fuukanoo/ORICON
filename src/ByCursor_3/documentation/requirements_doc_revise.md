# 要件定義書改訂版：異業種シナジー発見AI（CISF）

## 📋 変更履歴

**改訂理由**: ORICONデータの構造調査により、個人レベルでの満足度マトリックスが作成不可能であることが判明。属性集約アプローチを採用し、統計的に有意で実装可能な手法に方針転換。

**改訂日**: 2024年

---

## 🔄 主要変更点一覧

### 1. 基本アプローチの変更

| 項目 | **変更前（個人ベース）** | **変更後（属性集約）** |
|------|------------------------|----------------------|
| **データ構造** | respondent_id × brand_id の満足度マトリックス | demographic_group × brand_id の集約満足度マトリックス |
| **満足度取得** | 各個人が全ブランドを評価（架空の前提） | 各個人は主利用サービスのみ評価（実データ） |
| **マトリックス密度** | 仮想的に100%（実際は5%未満） | 30-50%（統計的に安定） |
| **サンプルサイズ** | 個人レベル（n=1） | 属性グループレベル（n=5-50） |

### 2. データ処理要件の変更

#### 変更前（FR-01）
```yaml
複数業種のExcel/CSVを読み込み、long形式に統合：
respondent_id, brand_id, industry_id, question_id, score
```

#### 変更後（FR-01 改訂）
```yaml
複数業種のExcel/CSVを読み込み、属性集約後にlong形式で統合：
demographic_group_id, brand_id, industry_id, question_id, 
aggregated_score, sample_count, confidence_interval
```

**新規追加（FR-01a）**: 属性項目の標準化
- SQ1（性別）: 1=男性、2=女性
- SQ2（年齢）: 実年齢 → 年齢層（5歳刻み）に変換
- SQ3（居住地）: 都道府県コード → 地域ブロック（都市部/地方）に集約
- SQ4/SQ5（職業/年収）: オプション属性として追加考慮

### 3. 満足度集約処理（新規追加）

**新規（FR-15）**: 属性グループ別満足度集約
- 各属性組み合わせ（性別×年齢層×地域）でグルーピング
- 最低サンプル数5以上のグループのみ採用
- 平均値、標準偏差、95%信頼区間を算出
- 欠損セル（サンプル不足）は補間または除外

**新規（FR-16）**: 集約品質管理
- マトリックス密度30%以上を維持
- 各ブランドで最低3つの有効属性グループを確保
- 統計的有意性検定（F検定、t検定）を実施

### 4. モデリング要件の変更

#### 変更前（HBモデル）
```yaml
ブランドα、業種δで順序ロジットモデル
個人レベルの応答をベースに階層ベイズ
```

#### 変更後（HBモデル改訂）
```yaml
ブランドα、業種δ、属性グループγで順序ロジットモデル
属性集約データをベースに階層ベイズ
γの効果も明示的にモデリング
```

#### VGAEモデルの変更
**変更前**: 個人の潜在表現学習
**変更後**: 属性グループの潜在表現学習
- ノード: demographic_group（約20-40グループ）
- エッジ: グループ間の類似性・補完性
- 学習対象: グループレベルの満足度パターン

### 5. 指標計算の変更

#### 変更前（FR-30）
```yaml
各ブランド×アンカーごとにμ、H、95%信頼区間を計算
```

#### 変更後（FR-30 改訂）
```yaml
各ブランド×アンカー×属性グループごとにμ、H、95%信頼区間を計算
属性重み付き平均でブランドレベルの指標を算出
```

**新規（FR-31a）**: 属性セグメント分析
- 年齢層別、性別別、地域別のΔμ、ΔH分析
- セグメント固有のコラボ機会発見
- 属性ごとの感度分析実装

### 6. UI要件の変更

#### 変更前（FR-42）
```yaml
グラフ画面：ノードサイズ=平均μ、線幅=Δμ、色=ΔH
```

#### 変更後（FR-42 改訂）
```yaml
グラフ画面：ノードサイズ=全属性統合μ、線幅=Δμ、色=ΔH
属性セグメント選択機能追加（年齢層/性別/地域フィルタ）
```

**新規（FR-44）**: 属性ドリルダウン機能
- ブランドクリック時に属性別の満足度分布表示
- 「20代男性」「30代女性」等のセグメント固有のインサイト
- 属性間のクロス分析（年齢×性別のヒートマップ）

### 7. 実装アーキテクチャの変更

#### データ処理層の変更
**変更前**: pandas中心の個人データ処理
**変更後**: pandas + groupby集約 + 統計的検定ライブラリ

**新規追加**: 集約処理レイヤー
```python
src/
├── data_processing/
│   ├── aggregation.py      # 属性集約エンジン（新規）
│   ├── demographic.py      # 属性標準化（新規）
│   └── quality_check.py    # 集約品質管理（新規）
```

#### モデリング層の変更
**HB用**: PyMC → 属性階層効果を明示的に扱う拡張モデル
**VGAE用**: PyTorch Geometric → 属性グループノードでのグラフ学習

### 8. 評価指標の変更

#### 変更前（FR-50）
```yaml
過去の既知コラボ10件でPrecision@5、AUC等を算出
```

#### 変更後（FR-50 改訂）
```yaml
過去の既知コラボ10件でPrecision@5、AUC等を算出
属性セグメント別の予測精度も評価
（例：20代向けコラボ、女性向けコラボの精度）
```

**新規（FR-53）**: 属性解釈性評価
- 各コラボ推奨の属性根拠説明
- 「30代女性に82%支持」等の定量的根拠提示
- 属性セグメント間の一貫性評価

### 9. 非機能要件の変更

#### 処理速度
**変更前**: 最大100ブランド × 1万回答
**変更後**: 最大100ブランド × 1万回答 → 40属性グループ × 100ブランド
（大幅な計算量削減により処理速度向上）

#### 説明可能性の強化
**変更前**: SHAP値のみ
**変更後**: SHAP値 + 属性セグメント分析 + 統計的有意性表示

### 10. 新規リスク項目

| リスク | 影響 | 対策 |
|--------|------|------|
| **属性グループのサンプル偏り** | 特定セグメントの過小評価 | サンプル数による重み付け、信頼区間表示 |
| **集約による情報損失** | 個人差の見落とし | 分散情報の保持、セグメント内ばらつき可視化 |
| **属性セグメント不足** | マトリックス密度低下 | 段階的集約（地域→都市部/地方等） |

### 11. 受け入れ条件の追加

**従来条件に加えて**:
- 各業種で最低30%のマトリックス密度を達成すること
- 属性セグメント別の説明精度が統計的に有意であること
- サンプル数5未満のセルは明示的に「データ不足」表示すること

## 📊 実装効果の期待値

### Before（個人ベース）- 実装困難
- マトリックス密度: < 5%
- 統計的信頼性: 低（サンプルサイズ1）
- 実装可能性: 困難（データ構造と不整合）

### After（属性集約）- 実装可能
- マトリックス密度: 30-50%
- 統計的信頼性: 高（サンプルサイズ5-50）
- 実装可能性: 高（実データ構造と整合）
- 追加価値: セグメント別インサイト獲得
