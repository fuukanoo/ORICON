## 🔧 属性セグメント集約処理（FR-04, FR-05）

### **重要要件（明記済み）**
```yaml
FR-04: 属性セグメント集約処理
  - 個人レベル → セグメントレベルでの分析
  - セグメント軸: 年収×年齢×性別×地域
  - 出力: segment_id, brand_id, industry_id, question_id, aggregated_score

FR-05: プライバシー保護
  - k-匿名性 ≥ 5 (各セグメントに最低5人)
  - 個人特定不可能な統計処理
  - セグメント統計のみでμ、H、信頼区間計算
```

### **実装時の必須チェック**
- [ ] 個人レベルデータを直接使用していないか
- [ ] セグメントサイズがk-匿名性を満たしているか  
- [ ] 属性データ（年収、年齢等）が正しく抽出できているか
- [ ] セグメント化ロジックが要件定義書と一致しているか

## 📊 データ処理パイプライン設計

### **段階的実装（要件定義書準拠）**
```
Stage 1: Raw Data Loading
  - Excel/CSV読み込み（複数業種対応）
  - ブランド評価列の検出（SQ6_1[x], SQ[x]パターン）

Stage 2: Attribute Extraction  🚨 NEW
  - 回答者属性データ抽出（年収、年齢、性別、地域等）
  - セグメント定義（年収帯×年代×性別×地域）

Stage 3: Segment Aggregation  🚨 NEW
  - 個人データ → セグメント統計に集約
  - k-匿名性チェック（セグメントサイズ≥5）
  - μ、H、95%信頼区間をセグメント単位で計算

Stage 4: Long Format Conversion
  - segment_id, brand_id, industry_id, question_id, score
  - Q1（総合）+ Q2（サービス16項目）+ Q10（コンテンツ48項目）

Stage 5: Anchor Alignment
  - 65項目 → 8アンカーへのマッピング
  - SBERT + コサイン類似度 + Softmax正規化
```
